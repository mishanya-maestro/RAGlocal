## Web UI (Flask)

Установка зависимостей (в venv проекта):

```bash
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запуск сайта (важно: тот же Python, куда ставили пакеты):

```bash
run.bat
```

или:

```bash
.\.venv\Scripts\python.exe src/flask_app.py
```

Не используйте голый `py -3 src/flask_app.py`, если пакеты ставили только в `.venv` —
тогда Flask не увидит `faster-whisper` (диск C: часто переполнен, и поставить пакет
в системный Python не получается).

Открыть в браузере:

```text
http://127.0.0.1:5000
```

Чат всегда работает в обычном режиме: ответ через RAG (поиск + контекст статей).

### 🎙️ Голосовой ввод (STT)

В композере есть кнопка микрофона: первое нажатие начинает запись, второе —
останавливает и распознаёт речь локально через Whisper (`faster-whisper`)
или через AssemblyAI, если задан ключ.

Кэш моделей Whisper хранится в `.cache/huggingface` внутри проекта (диск D:),
чтобы не упираться в полный диск C:.

Опционально — ключ AssemblyAI в `.env`:

```text
ASSEMBLYAI_API_KEY=ваш_ключ
```

Голосовая запись работает только по `localhost` или по HTTPS (требование
браузера для `getUserMedia`).

### Анализ документов на соответствие законодательству

Вкладка **Анализ документа** (`/analyze`) позволяет загрузить PDF, DOCX, TXT или фото документа (PNG, JPG, WEBP, BMP, GIF, TIFF) и получить проверку на соответствие действующему законодательству РБ.

Фото распознаются через **Tesseract OCR**. Для работы на Windows установите:

```bash
winget install --id UB-Mannheim.TesseractOCR --source winget
```

И скачайте русский языковой пакет в папку `C:\Program Files\Tesseract-OCR\tessdata`:

```powershell
Invoke-WebRequest -Uri "https://github.com/tesseract-ocr/tessdata/raw/main/rus.traineddata" `
  -OutFile "C:\Program Files\Tesseract-OCR\tessdata\rus.traineddata"
```

Если `tesseract.exe` не в `PATH`, приложение автоматически ищет его в стандартных папках `C:\Program Files\Tesseract-OCR` и `C:\Program Files (x86)\Tesseract-OCR`.

Архитектура — **гибрид «Шаблон + LLM»**:

1. **Шаблон** — стабильная проверка структуры.
   - Для каждого типа документа (исковое заявление, договор, трудовой договор, приказ) в `src/templates_docs/` лежит образец правильного документа.
   - В `src/document_templates.py` описаны обязательные и рекомендуемые разделы с ключевыми словами.
   - Движок сравнивает загруженный документ с шаблоном: находит/отсутствующие разделы выводятся без участия LLM — быстро и надёжно.
2. **LLM** — проверка содержания найденных разделов.
   - Для каждого найденного раздела собирается релевантный контекст из законов (ChromaDB).
   - Одним вызовом LLM (`qwen3.5:4b`) проверяется содержание всех найденных разделов.
   - LLM выдаёт конкретные замечания: цитату, нарушенную норму, предложение по правке, severity и уверенность.
3. **Результат в UI**:
   - тип документа и извлечённые реквизиты;
   - сводка по замечаниям (критично / важно / рекомендация);
   - карточка с образцом правильного документа и кнопкой скачивания;
   - структурный отчёт: какие разделы найдены, какие отсутствуют;
   - карточки замечаний с цитатами, ссылками на нормы и предложениями по правке;
   - фильтры и экспорт отчёта в Markdown.

Схема работы: `architecture_hybrid.svg` (и исходник `architecture_hybrid.mmd`).

Юридический корпус проекта расширен placeholder-актами для демонстрации архитектуры:
- Гражданский кодекс РБ (`data/GKrb.txt`) — договоры;
- Трудовой кодекс РБ (`data/TKrb.txt`) — трудовые договоры и приказы;
- Гражданский процессуальный кодекс РБ (`data/GPKrb.txt`) — исковые заявления;
- Закон о защите прав потребителей (`data/ZPPPT.txt`) — потребительские договоры.

#### Распознавание фото (OCR)

Для загрузки фотографий документов необходим Tesseract OCR с поддержкой русского языка.

Установка через winget (рекомендуется):

```bash
winget install --id UB-Mannheim.TesseractOCR --exact
```

Или скачайте установщик с https://github.com/UB-Mannheim/tesseract/wiki и добавьте папку `Tesseract-OCR` в системную переменную `Path`.

После установки перезапустите терминал/IDE и убедитесь, что команда `tesseract --version` работает.

Для production-качества эти файлы необходимо заменить на официальные тексты с Национального правового интернет-портала РБ, после чего перестроить индексы:

```bash
.\.venv\Scripts\python.exe src\generate_fulltext.py
.\.venv\Scripts\python.exe src\ingest.py
```

### Мои корпуса (пользовательские базы для RAG)

Раздел **Мои корпуса** (`/corpora`) позволяет загружать свои документы (PDF, DOCX, TXT, фото) и создавать из них отдельные векторные базы для режима **Вопрос**.

Как это работает:

1. **Создание корпуса** — на странице `/corpora` укажите название и описание, нажмите «Создать корпус».
2. **Загрузка документов** — перетащите файлы в карточку корпуса или выберите через диалог. Документы распознаются, разбиваются на чанки и индексируются в отдельную коллекцию ChromaDB.
3. **Активация** — нажмите «Выбрать» в карточке корпуса (или выберите корпус в выпадающем списке в композере чата). В статусе появится «Активирован пользовательский корпус».
4. **Вопросы по корпусу** — в режиме **Вопрос** (/ или `/corpora`) задайте вопрос. RAG будет искать только в активном корпусе, а не в системной базе законов РБ.
5. **Возврат к системной базе** — выберите «Системная база законов РБ» в выпадающем списке или нажмите «Сбросить» на странице корпусов.

Управление:

- **Удалить корпус** — удаляет коллекцию и все загруженные файлы.
- **Удалить документ** — пересоздаёт индекс корпуса без этого документа.
- **API**:
  - `GET /api/corpora` — список корпусов и активный корпус;
  - `POST /api/corpora` — создать корпус (`{name, description}`);
  - `DELETE /api/corpora/<id>` — удалить корпус;
  - `POST /api/corpora/<id>/documents` — загрузить файлы (`multipart/form-data`, поле `documents`);
  - `DELETE /api/corpora/<id>/documents/<doc_id>` — удалить документ;
  - `POST /api/corpora/<id>/set-active` — сделать корпус активным;
  - `POST /api/corpora/clear-active` — сбросить активный корпус.

Метаданные корпусов хранятся в `corpora.json`, исходные файлы — в папке `corpora_storage/`, векторные индексы — в `chroma_db/`.
